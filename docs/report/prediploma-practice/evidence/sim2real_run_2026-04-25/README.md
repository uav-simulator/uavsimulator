# Sim-to-real run — 2026-04-25

Первый физический прогон обученной в Unity-симуляции policy на реальном KS0223
по картонной L-трассе. Цель спринта 3: end-to-end проверка sim-to-real пайплайна
+ safety wrapper в backend.

**Итог:** sim-to-real **fail на v6** — 0/1 успешных запусков, 1 контакт со
стеной за 1 прогон → прерван по протоколу безопасности (≥1 контакт = стоп).
Корневые причины зафиксированы ниже.

---

## 1. Сетап

### Робот
- **Модель:** Keyestudio KS0223 (4-колёсный differential drive, 15×25 см)
- **Камера:** OV/USB 320×240 на servo-мачте 9 см, наклонена вниз ⇒ виден
  в основном пол + ближние объекты (см. [cam_initial.jpg](./cam_initial.jpg)).
- **Сенсоры:** HC-SR04 ультразвук на носу, IR-tracking, OLED 0.91" с IP/state.
- **Связь:** Mac (192.168.1.35) ↔ Pi (192.168.1.121) по WiFi. Латентность ping
  4 мс, потерь 0%. TCP `:5051` для команд, UDP `:5051` для камеры (JPEG
  q=95, ~19 КБ/кадр, ~34 fps на приёмнике).

### Трасса (картон, L-форма)
- Сегмент A: ~110 см, сегмент B: ~90 см (Никита подтвердил ±10 см).
- Ширина коридора 60 см, стены 25 см (плотный картон, треугольные подпорки).
- **Без ArUco на финише** (в sim был, на физике решили без — финиш
  определяется через E-stop на стене).
- Стартовая позиция: вдоль сегмента A, лицом к финальной стене.

### Backend
- ASP.NET Core, `dotnet run --launch-profile http`, порт `5287`.
- ModelRegistry / AutopilotService / AutopilotSafetyFilter активны.
- Safety params (`appsettings.json` → `AutopilotSafety`):

  ```
  EStopDistanceM: 0.12   (12 см ультразвук)
  EStopHoldMs:    500
  ThrottleMax:    0.5    (50%)
  RampUpMs:       200
  DeadmanMs:      300
  ```

### Модель
- **`cardboard-corridor-ppo-v6` 1.0.0** (250k шагов, 100% SR на L-corridor sim
  eval, reward 117). Источник: `python/training/artifacts/cardboard-corridor-ppo-v6/`.
- **ONNX отсутствовал** — экспортирован на лету из SB3 zip
  ([export_v6_onnx.py](../../../../python/training/export_v6_onnx.py)),
  3.5 МБ, opset 18, входы `image (1,84,84,3) float32` + `ultrasonic (1,1) float32`,
  выход `action (1,2)` ∈ `[-1,1]`.

## 2. Калибровка

Линейная скорость замерена двумя короткими DirForward-бёрстами с замером
рулеткой (см. [calibration.json](./calibration.json)).

| Burst | DurCmd | Ultrasonic Δ | Ruler факт | v real |
|-------|--------|--------------|------------|--------|
| 1     | 0.5 с  | 13.3 см      | 35 см      | 0.70 м/с |
| 2     | 0.3 с  | 16.3 см      | 23 см      | 0.77 м/с |

**v_real ≈ 0.73 м/с** при `drive_speed_percent: 80` на роботе.

### Наблюдения по ультразвуку
- **Абсолютное расстояние:** робот в 56 см от стены показал ультразвук
  42.8 см → занижение ~25%.
- **Дельта при движении:** систематически занижает на 30–50% (фильтр
  сглаживания + sample interval 150 мс).
- **Импликация для safety:** E-stop порог 12 см ультразвук = ~16 см
  фактически. Безопасно (раньше тормозит, не доходит до контакта), но
  робот может «недоехать» до конца сегмента.

### Yaw rate — пропущена
В узком коридоре (60 см) разворот робота развёл бы его боком к стенам.
Калибровка на пустой комнате не делалась (Никита оставил робота на трассе).
Не критично: автопилот работает дискретными командами (DirLeft/Right/Forward/
Back/Stop), а не угловыми скоростями — yaw rate важна только для retraining.

## 4. Stage 1 / Run 1 — autopilot 50% throttle

### Параметры
- `loopIntervalMs: 140` (≈7 Hz инференс)
- `ThrottleMax: 0.5`
- Старт ультразвук: 95.95 см

### Метрики
- **Длительность:** 8.73 с
- **Шагов:** 57 (в среднем 6.5 шагов/сек)
- **E-stop:** сработал на 10.49 см ультразвук, `eStopActive=true`, count=1
- **Финал:** `final_reason: "estop_triggered"`
- **Дельта позиции:** ультразвук 95.95 → 52.87 см (по логам), но это не
  отражает реальный путь — робот **крутился на месте** и задевал стену.

### Поведение модели

Модель v6 практически весь прогон выдавала **`steer = +1.00`** (полный левый
поворот), throttle прыгал между +0.5 и -0.95. AutopilotService в backend
маппит это в дискретные команды через
[`ResolveCommand`](../../../../src/ks0223-web-mac/backend/Services/AutopilotService.cs):

| `throttle` | `steer` | Команда |
|------------|---------|---------|
| > 0.45     | > 0.45  | `DirLeft` (→ ротация) |
| ∈ [0.15, 0.45] | > 0.55 | `DirLeft` |
| ∈ [-0.25, 0.15) | > 0.55 | `DirLeft` (steer override) |
| < -0.25    | (любой) | `DirBack` |

Из 57 шагов: **DirLeft ≈ 45, DirBack ≈ 10, DirStop ≈ 1, DirForward ≈ 0–2**.
Робот фактически **никогда не ехал прямо**.

### Физический результат (со слов Никиты)

> «Он начал крутиться вокруг себя и снёс сразу же правую стену целиком.»

- Робот выполнил серию ротаций влево.
- Радиус разворота 4-колёсного diff-drive robot ≈ ширина базы / 2 = ~10 см.
- Робот старт-позиция в ~30 см от правой стены ⇒ при скользящем движении
  при ротации задний/передний угол выходил за этот радиус и встретил картон.
- Картонная стена сегмента А завалилась полностью.

### Снапшоты с пути

- [snap00](./stage1/run1_snap00.jpg) — старт. На кадре виден диван и
  дверь — **камера направлена не в коридор, а в комнату**. Это либо
  результат разворота во время калибровки, либо неправильная стартовая
  ориентация. В любом случае модель видит сцену совершенно непохожую на
  тренировочный distribution.
- [snap04](./stage1/run1_snap04.jpg) — середина, motion blur от вращения.
- [snap07](./stage1/run1_snap07.jpg) — момент E-stop, белая стена крупно.

## 5. Sim vs Real — gap анализ

| Метрика                              | Sim eval (v6 на L-corridor) | Real (Run 1) |
|--------------------------------------|------------------------------|--------------|
| Success rate                         | 100% (20/20)                 | 0% (0/1)     |
| Avg reward                           | +117                         | n/a          |
| Avg steps to finish                  | 13–14                        | 57 (E-stop)  |
| Контактов со стенами                 | 0                            | 1 (правая)   |
| Доминирующая команда                 | DirForward / умеренные left/right | DirLeft (=ротация) |
| Visual: разрешение                   | 84×84 RGB (после resize)     | 320×240 → 84×84 |
| Visual: камера                       | sim фронтально, смотрит вдоль коридора | реал наклонена вниз, видит пол + мебель сбоку |
| Латентность инференс→команда         | 0 (синхронно в env)          | ~140 мс loop + ~10 мс backend ONNX |
| Throttle dynamics                    | непрерывный [-1,1]           | дискретные команды |

### Корневые причины провала (в порядке убывания вклада)

1. **Visual domain gap (наибольший).** Модель тренировалась на чистых Unity
   рендерах прямого вида коридора. На реальном кадре она видит пол с
   древесной текстурой, кусок дивана, оранжевую тумбу — никаких видимых
   стен коридора в фокусе. Распределение пикселей out-of-distribution →
   policy collapses to constant `steer=+1`.

2. **Dynamics / control mapping gap.** В Unity `vehicle.prometeo.sport.v1`
   при `(throttle=+0.5, steer=+1)` исполняет дугу вперёд+влево
   (Ackermann-подобная физика). На реальном KS0223 эта же пара уходит в
   дискретный `DirLeft` через
   [AutopilotService.ResolveCommand](../../../../src/ks0223-web-mac/backend/Services/AutopilotService.cs:367) —
   ротация на месте обоими бортами. Модель ожидала forward+left arc,
   получила in-place rotate.

3. **Отсутствие domain randomization при тренировке.** v6 училась на
   фиксированной картонной L-трассе в Unity без augment'ов
   (lighting/texture/blur/jitter камеры).

### Что подтвердилось как working
- ✅ **Safety wrapper** сработал ровно как ожидалось: E-stop @ 12 см
  ультразвук, мгновенно остановил робота, count=1 в `eStopTriggerCount`.
- ✅ **TCP control loop** — без drop'ов команд, ~7 Hz стабильно.
- ✅ **Camera UDP pipeline** — 30+ fps на приёмнике, JPEG валидный.
- ✅ **ONNX inference** в backend — без падений на 57 шагах.
- ✅ **Telemetry** — ultrasonic / IR / config поступали без ошибок.

То есть **инфраструктура sim-to-real готова**, проблема исключительно в
**policy generalization**.

## 6. Lessons & future work

### Критические доработки перед следующим sim-to-real тестом
1. **Domain randomization при тренировке** — randomized texture/lighting,
   noise, motion blur. Это базовое требование для visual sim-to-real,
   v6/v7/v8 его не имели.
2. **Camera angle alignment** — поднять servo камеры так, чтобы реальная
   точка обзора совпадала с симуляционной. У KS0223 камера на двух servos
   (pan + tilt), API не вызывалось — оставлено на дефолт.
3. **Vehicle plugin recalibration** — ввести в Unity модель ks0223 с
   in-place rotation как у diff-drive (без forward arc на DirLeft). Либо
   менять `ResolveCommand` чтобы (throttle>0, steer>0) → новая команда
   `DirArcLeft` (одна сторона быстрее, без stop).
4. **Тренировка с реальными камерами/UDP-стримом** (или хотя бы с
   recorded real-world подмножеством датасета).

### Дополнительные идеи
- Альтернативные модели (v7@35k, v8@120k) которые видели maze-curriculum —
  могут быть более устойчивы к вариативности сцены, но визуальный gap у
  них тот же (тренировка в Unity без real-image augment'ов).
- ArUco на финише (как в раннем плане) — хотя бы один gradient,
  понятный модели в реальной среде.
- Sensor-only fallback policy (без камеры, по ультразвуку) — sanity-baseline
  для сравнения.

## 7. Верификация безопасности

Sprint 3 главный артефакт — `AutopilotSafetyFilter` в backend. Этот тест
показал что фильтр **корректно работает на проде**:

| Фича | Ожидание | Подтверждено |
|------|----------|--------------|
| E-stop @ 12 см | Триггерится при пересечении порога | ✅ Сработал на 10.49 см ультразвук |
| Sticky 500 мс  | Удерживает stop | ✅ После триггера autopilot не возобновлял команды |
| Throttle clip 50% | `\|throttle\|` ≤ 0.5 после фильтра | ✅ В логах `last_throttle` всегда ∈ [-1,+0.5] |
| Ramp-up 200 мс | Плавный старт | ✅ Первый шаг throttle 0.17 (clipped from raw output) |
| Deadman 300 мс | Не сработал — связь стабильна | n/a (нет события) |
| `eStopTriggerCount` сброс на старте | Каждая сессия с 0 | ✅ Старт=0, после E-stop=1 |

Unit-тесты (9/9 в `backend.Tests/AutopilotSafetyFilterTests.cs`) +
этот production-проход доказывают полную интеграцию.
