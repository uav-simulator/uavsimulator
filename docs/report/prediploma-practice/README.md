# Преддипломная практика 2026

## Назначение
Черновики и входные материалы для преддипломной практики по магистерской работе в репозитории `uav-simulator`.

## Период практики
- Сроки: с 21.03.2026 по 18.05.2026.
- Общая трудоемкость: 12 з.е. / 432 акад. часа.
- Этапы:
  - организационный этап: 8 акад. часов;
  - экспериментальный этап: 406 акад. часов;
  - заключительный этап: 18 акад. часов.

## Состав папки
- `НМГоровенко_ПреддипломнаяПрактика_ПромежуточныйОтчет1.docx` — итоговый DOCX промежуточного отчета №1.
- `build_interim_report_1.py` — генератор итогового DOCX на основе принятого отчета-донора.
- `sprint-1-changelog.md` — журнал изменений по Спринту 1 (21.03.2026-04.04.2026) для загрузки в электронный курс.
- `individual_assignment_draft.md` — рекомендуемый черновик индивидуального задания.
- `calendar_plan.md` — календарный план прохождения практики с привязкой к контрольным точкам курса.
- `interim_report_1_draft.md` — заготовка промежуточного отчета №1.
- `source/vypiska_trebovaniya_md_2026.pdf` — приложенная выписка по магистерской диссертации.
- `source/prediplomnaya_praktika_programma.pdf` — приложенная программа преддипломной практики.

## Контекст
- Магистерская работа в репозитории описана как разработка расширяемого Unity-симулятора для обучения и проверки моделей управления наземными роботами.
- По факту реализации в проекте уже есть Unity runtime, HTTP JSON API, Python SDK, ROS2 bridge, плагинная архитектура треков и роботов, а также sim-to-real контур для `KS0223`.
- Отчет по технологической практике остается основным стилевым и структурным образцом: `docs/report/practice/practice_report_2.docx`.
- В качестве рабочей рамки для преддипломной практики выбран исследовательско-прикладной вариант: разработка и исследование расширяемого Unity-симулятора и программного контура sim-to-real для обучения и проверки моделей управления.

## Что требует согласования
- Официальная формулировка темы магистерской диссертации из выписки.
- Финальная формулировка индивидуального задания с научным руководителем.
- Состав разделов итогового отчета по стандарту СФУ в финальной DOCX-версии.

## Правила переиспользования
- Новые академические отчеты и заготовки для магистерской работы собирать от принятого SFU-образца, а не с нуля.
- Содержательные заготовки для новых отчетов и магистерской держать в Markdown рядом с генератором, чтобы их можно было переиспользовать без ручного копирования из Word.
- Итоговый файл называть по шаблону `ИнициалыФамилия_ТипДокумента_ВерсияИлиЭтап.docx`.
- Перед сдачей проверять итог через Word/PDF-рендер, особенно титульник, содержание, переходы страниц и подписи.
- Если автоматическое содержание в Word ведет себя нестабильно, фиксировать итоговый вариант как детерминированный статический блок.
