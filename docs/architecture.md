## Purpose
Зафиксировать целевую архитектуру, границы модулей и правила изоляции исследовательского кода.

## Assumptions
- Текущие реализации будут добавляться постепенно; этот документ описывает целевую структуру.
- Содержимое сцен/префабов не предполагается без аудита.

## Decisions
- Границы кода:
  - Production: `Assets/Scripts/Core`, `Assets/Scripts/Vehicles`.
  - Research: `Assets/Scripts/AI` (эксперименты, прототипы, исследовательские алгоритмы).
- Базовые модули симулятора:
  - Environment: сцена/трасса, спавн/сброс, окружение.
  - Vehicle: физика, интерфейс управления, сенсоры.
  - API: стабильные контракты управления/наблюдений/событий.
  - Experiments: логирование, конфиги, артефакты запусков.
- Инварианты:
  - Исследовательский код не должен “протекать” в production.
  - Изменения сцен и ProjectSettings делаются осознанно и фиксируются в задачах.

## Decision Records
### DR-001: Таймстемпы и доставка кадров камеры
Assumptions:
- Клиент (Python) должен синхронизировать команды, состояние и кадры между процессами.

Decisions:
- Базовый `timeBase`: `unix_ms`; допускается `sim_ms` для внутренних метрик.
- Кадры камеры по умолчанию доставляются отдельно от JSON (через стрим/ссылку), JSON режим с base64 используется как fallback.
